# 悬浮窗功能恢复与紧凑界面

日期：2026-09-24。本文记录当前工作区修改；未编译、未验机，不代表已发布。

## 对照与根因

对照上游 v1.3 发布提交 `971b137` 的 `app/src/main/java/com/jev/probe/overlay/OverlayController.kt`、本 fork 的 HEAD，以及本轮开始时未提交的 Compose 悬浮窗实现。

主要退化位于悬浮窗迁移层：旧能力仍有回调或数据字段，但未接入新的 Compose UI。长按菜单被注释，采集预览只有 TODO，复制和重新分析入口缺失。单一 loading/error 分支又让回复生成或失败遮住已返回的判断。风险等级被误当作 0～1 色彩分量，主题和透明度没有作为可观察状态刷新。

| 能力 | 本轮处理 |
| --- | --- |
| 手动分析、重新分析 | 恢复入口；重新分析固定在面板底部 |
| 风险、意图、置信度、需求、行动、回复时机、紧张缓解 | 恢复中文详情；使用等级阈值显示风险圆点 |
| 回复排序、推荐概率、复制、填入 | 独立操作，点击正文不触发填入；不自动发送 |
| 截屏识别、存联系人、设置、隐藏 | 恢复长按菜单，标题栏也有菜单入口；按回调可用性展示 |
| Xposed 采集核对 | 展示最近 6 条正文及我/对方方向，仅保存在内存 |
| 知识库与采集来源 | 恢复知识库/历史数量及 OCR 等来源说明 |
| 两路结果反向到达、单路失败 | 判断与回复分别维护状态，已成功内容继续可见 |
| 主题、透明度、拖动、滚动 | 监听设置；悬浮球与面板标题各自处理拖动；限制内容高度并内部滚动 |
| 隐藏、会话变化、旧结果 | 分析代次校验，移除窗口时释放 Compose、监听器和 ViewModelStore |

恢复填入入口时同步增加无障碍目标核对：包名、当前聊天页、标题和消息签名不匹配时仅复制。节点无法核对正文的 OCR 场景也会走复制，不冒险填到不明输入框。Xposed 保留宿主会话校验。

## 用户确认后的视觉参数

根据用户提供的空面板、快捷菜单和分析结果截图，收紧了面板与菜单宽度；标题区显示“按住移动”，菜单改为单列紧凑行，回复卡片的底色增强文字对比。面板透明度仍读取应用设置。

根据后续结果截图，右上角的字体尖角改为居中的矢量“收起为悬浮球”短横线；推荐回复保留正文和概率，“复制 / 填入”使用独立胶囊按钮。当前按钮高度为 26dp，仍需验机检查触摸可用性。

- 分析面板宽不超过 252dp 或屏宽 84%，菜单不超过 220dp 或屏宽 74%；窄屏留出拖动空间。
- 内容区最高为 236dp 或屏高 30% 中较小值，长内容滚动；头部和重新分析位于滚动区外。
- 标题 13sp、正文 12sp、辅助信息 10～11sp；保留系统字体缩放。
- 面板底色使用 `Prefs.overlayOpacity`，不对整层设置 alpha；正文与图标保持不透明，回复卡片仅叠加浅色底。
- 悬浮球视觉直径 44dp、触摸区 48dp、图标 28dp；面板主操作按钮高 34dp，回复操作按钮高 26dp。
- 展开面板按住标题区域拖动，位置单独保存到 `Prefs.panelX/panelY`；收起与重开恢复位置，改变方向或内容高度时按实测尺寸约束在屏内；菜单按钮和内容滚动独立处理。
- 新增 `ic_overlay_route.xml`：对话气泡与分岔路线，沿用应用图标语义，单色矢量适配深浅主题；风险圆点独立显示。

## 修改文件

- `overlay/OverlayController.kt`：状态、窗口、主题、透明度、拖动及生命周期。
- `overlay/OverlayCompose.kt`：完整功能面板、菜单、预览、紧凑排版与图标引用；此文件原本就是未跟踪的本地迁移文件。
- `core/Prefs.kt`：展开面板的位置字段，与悬浮球位置分开。
- `capture/ChatCaptureService.kt`：分析结果代次、两路完成状态、会话变化及填入目标核对。
- `xposed/XposedCaptureRuntime.kt`：分析代次和两路完成状态。
- `app/src/main/res/drawable/ic_overlay_route.xml`：专用矢量图标。

以上 Kotlin 源码路径均相对于 `app/src/main/java/io/github/liaong13/dialogueroute/`。同次提交还包含任务开始前的 Gradle 和主界面本地修改；没有推送或安装 APK。
